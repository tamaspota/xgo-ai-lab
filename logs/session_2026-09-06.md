Decide whether to continue repairing the unsupported 2021 XGO-Mini STM32/K210 electronics or move to a supported retrofit while preserving the original chassis and 12 servos.

Current state: **waiting for shipment/tracking and exact board details**.

## Confirmed technical details from vendor

The replacement ESP32 board:

- is a newer adapted revision, not the old STM32 V2.5 board;
- uses the standardized XGO serial command protocol;
- supports the core command set used by `xgolib`;
- supports normal locomotion, pose adjustment and kinematics calls via Python;
- exposes an external **3.3 V TTL UART** for Raspberry Pi / SBC / PC;
- UART signals are TX/RX/GND;
- can connect directly to Raspberry Pi GPIO without a level shifter;
- will be accompanied by the exact firmware version/model profile and command mapping required for initialization.

Vendor will not provide the legacy servo-bus protocol, old board schematic or complete legacy hardware documentation.

## Current-generation parts compatibility

Vendor stated that latest Lite3 / CM5 AI modules and modular robotic arms are not direct plug-and-play parts for the original chassis because newer generations have different mounting, structural cable routing and integration.

Therefore:

- do not attempt to turn the old robot into a literal Lite3/mini2 by buying the full current head/arm stack;
- use the ESP32 replacement as the supported low-level motion layer;
- build any future upper compute/HMI layer as secondary development.

## Current-generation research completed today

Official XGO documentation updated in August 2026 shows the current quadruped driver-board family using **ESP32-WROVER-B**, onboard IMU, servo/switch/power interfaces, external 5 V / 3.3 V serial communication, reset controls and a high-current 5 V / 6 A DC-DC subsystem.

Current firmware documentation maps model prefixes:

- `M` -> XGO-mini2S;
- `L` -> XGO-lite3;
- `R` -> XGO-Rider2;
- `W` -> XGO-mini3W.

Current official `xgolib` repository reports version **1.4.2**, default baud **115200**, and auto-detection from firmware prefixes.

ELECFREAKS XGO2 architecture documentation also confirms the modern split architecture:

- ESP32 lower controller handles power, servo drive and gait;
- upper CM4/CM5 communicates over serial;
- chassis uses serial-bus servos;
- two 18650 cells are used in XGO2;
- current XGO-mini2 driver-board schematic is publicly linked.

This makes it plausible that the incoming retrofit board is physically/electrically related to the current XGO-mini2 driver family, but this is **not yet confirmed**. Vendor described it as an adapted replacement revision.

Detailed research recorded in `docs/ESP32_RETROFIT_RESEARCH.md`.

## Unified Firmware Flash Center discovery

Tamás inspected the current Luwu Dynamics web firmware tool at `https://tools.luwudynamics.ai/`.

Observed current XGO targets include:

- XGO-mini2S;
- XGO-lite3;
- XGO-mini2SW;
- XGO-Rider2;
- XGO-Ranger.

The UI presents these as ESP32 web-flash targets. The XGO-mini2S page observed on 2026-09-06 shows firmware **7.1.3**, dated **2026-08-01**, with a changelog mentioning improved gait stability and a Bluetooth disconnection fix.

This is important because, if the incoming retrofit board identifies as a supported current XGO profile — particularly an `M` / Mini-family profile — the official web flasher may provide a clean future firmware-update path.

Do not flash on arrival until the exact shipped board/profile is identified. Preserve the vendor firmware first and use Pengfei's supplied profile/command mapping as the source of truth.

## Chosen project direction

Target architecture:

```text
original aluminum chassis
+ original 12 servos
+ purchased vendor ESP32 motion board
+ optional upper layer after motion validation
    - legacy K210 temporarily, or
    - existing Raspberry Pi 4B, or
    - compact ESP32-S3 HMI
+ display/camera only if actually useful
+ network connection to PC / Local GPU Helper
```

The display is not a priority before locomotion works. Phone/web control may make a large onboard display unnecessary.

## Battery decision

Board-only was chosen because it reduces retrofit cost from USD 75 to USD 50.

Tamás already has several 18650 cells from an older solar project. Plan:

- wait for the incoming board;
- verify power connector, polarity and voltage requirement;
- use two matched healthy cells for a short 1–2 minute first test;
- only buy a stronger matched pair if existing cells sag under servo load;
- consider LiPo only later after the board's exact power design is known.

## HMI / camera research direction

No new display/camera purchase now.

Possible later upper-controller choices:

1. test original K210 head if UART-compatible;
2. use existing Raspberry Pi 4B over vendor-confirmed 3.3 V UART;
3. use a compact ESP32-S3 display/camera/Wi-Fi board.

Luwu Dynamics' current open-source `RIG-Omni` project demonstrates an ESP32-S3 system with Wi-Fi/BLE, 240x240 SPI display, camera, audio and XGO UART protocol. It is a useful design reference, not a proven drop-in module for this chassis.
